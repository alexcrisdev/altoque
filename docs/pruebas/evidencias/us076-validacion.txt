US-076 — Pagar con tarjeta online (Stripe, modo prueba)
Responsable: Alexander. Verificado el 10/11/2026 (America/Lima).
Stripe: entorno de prueba (sandbox) "Entorno de prueba de ALTOQUE", API 2026-10-28.endive,
librería stripe 23.1.0. Proyecto Supabase altoque-dev. No se incluyen claves ni tokens.

Cómo funciona
1. El cliente pulsa «Pagar con tarjeta» en su celular (carta de la mesa o página de su
   pedido para llevar).
2. El servidor saca la cuenta del token del QR, pide el saldo a la base
   (saldo_cuenta_online) y crea la sesión de Stripe Checkout en soles.
3. El cliente paga en la página de Stripe. AlToque nunca ve la tarjeta.
4. Al volver ve «Procesando pago…» hasta que llega el webhook.
5. Stripe llama a /api/stripe/webhook con un evento firmado. Si la firma es válida, se
   registra el pago (registrar_pago_stripe) como CARD, CONFIRMED, sin cajero.
6. Caja lo ve como «Stripe (online)» con su referencia pi_...

Cómo repetir la prueba en local
1. .env.local con STRIPE_SECRET_KEY=sk_test_... y STRIPE_WEBHOOK_SECRET=whsec_...
   (este último sale de: stripe listen --print-secret).
2. Terminal 1: npm run dev
3. Terminal 2: stripe listen --forward-to localhost:3000/api/stripe/webhook
4. Abrir una mesa desde /mesero, pedir algo desde el QR de la mesa y pulsar
   «Pagar con tarjeta». Pagar con 4242 4242 4242 4242.
5. Revisar /caja: el pago aparece como «Stripe (online)».
6. Webhook sin firma:
   curl -X POST http://localhost:3000/api/stripe/webhook -d '{}'   (debe dar 400)

Riesgo conocido
Si la cuenta se paga en caja mientras el cliente está en la página de Stripe, Stripe sí
cobra pero AlToque no registra un pago de más. El log del servidor muestra
"REQUIERE REEMBOLSO" con el pi_..., y el reembolso se hace desde el dashboard de Stripe.
